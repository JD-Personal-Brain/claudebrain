# How I'd run the work: the six-step workflow

_Working copy of the designed page. Source: `product-framework.md`._

**One line:** every AI product goes through six steps, each ending in a go/no-go
gate, with governance running through all of them. The first pass is fast;
then steps 3–6 repeat in short cycles, and each new set of features takes a
quick pass through Discover and Define.

| Step | Question | Governance thread | Gate |
|---|---|---|---|
| 1. Discover | Which problem or opportunity is worth solving first? | Risk partners briefed on the idea | Sponsor agrees on the target, the measure and today's baseline |
| 2. Define | What exactly do we build first, and how will we know it worked? | Risk intake and early rating; data use approved | Brief, data contract and risk rating agreed; value model shows payback within [X] months |
| 3. Build | What's the smallest version users will use and trust? | Controls built in; test set created | Meets the quality bar in testing; every control has proof |
| 4. Govern and test | Is it safe, fair and controlled? | Formal validation and sign-offs | All sign-offs recorded; monitoring plan agreed |
| 5. Release and adopt | Will users use it every week? | Live monitoring; incident process | Weekly use and results hit targets; no serious incidents; long-term owner confirmed before scaling |
| 6. Measure and iterate | Is it delivering the outcome, and what comes next? | Ongoing monitoring | Each month (and at the end of each wave): keep, change or stop each feature; each quarter: invest more, adjust or stop overall |

**Inside each step:** one item per playbook sub-step, as listed in `product-framework.md` ("What happens in each step").

**Building starts on day one** (from the RM plan): a working prototype in week 1, used in discovery. The pace is set by data access and review, not build time.

**Who decides:** sponsor (outcome, funding, go/no-go) · user leaders and pilot users (workflow, feedback) · product manager (scope, priorities, trade-offs; owns the product until a long-term owner is named) · long-term owner (identified during the project, for example someone in a revenue line; named in Define if known, confirmed before scaling) · data owners (what data may be used) · platform teams (technical design) · model risk (risk rating, approval) · compliance, privacy and security (controls, sign-off) · operations (running it day to day).

**Five measures:** usage · quality · business impact · adoption · risk and controls.

**AI principles:** two kinds of agents (for the team, for users) · assistive first · one job each · built where the work happens.
